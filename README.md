# 影片字幕翻譯器

選取多個影片 → 自動辨識語音 → 翻譯 → 產生或嵌入字幕。
全部跑在自己的電腦上，可以完全離線、不花錢，影片內容不會送到任何外部服務。

為 Windows + WSL2 + NVIDIA 顯示卡的環境所寫。所有程式、虛擬環境、模型都裝在專案資料夾內，
不會動到系統，安裝過程也不需要 `sudo`。

> 本專案供教學與研究使用。請自行確認所處理影片的著作權，以及下方各模型的授權條款。

## 它能做什麼

- **批次處理**：一次選多個影片，或整個資料夾（含子資料夾）排隊處理
- **語音辨識**：faster-whisper，GPU 加速，日/中/韓/英實測皆可用
- **翻譯**：本地開源模型，完全離線免費（另有 Google 免費翻譯當備援）
- **字幕輸出**：外掛 `.srt`、嵌入軟字幕、或燒錄成硬字幕
- **雙語字幕**：譯文在上、原文在下
- **術語表**：指定角色名、專有名詞對照，讓整部影集譯名一致
- **繁體中文友善**：中文辨識結果自動轉台灣正體，譯文自動換成台灣用語
- **預估時間**：辨識一完成就告訴你翻譯還要等多久

## 系統需求

| 項目 | 需求 |
| --- | --- |
| 作業系統 | Windows 10 / 11 |
| WSL2 | Ubuntu（預設設定寫 `Ubuntu-24.04`）|
| Windows 端 Python | 3.8 以上，只用到標準函式庫（圖形介面）|
| 顯示卡 | NVIDIA（非必要，但沒有的話會慢上數十倍）|

> **沒有 WSL？** 以系統管理員開啟 PowerShell，執行 `wsl --install -d Ubuntu-24.04`，重開機後照提示建立使用者。

## 安裝

```bash
git clone https://github.com/Hung-NCKU/translator.git
cd translator
```

然後雙擊 **`安裝環境.bat`**（或在 WSL 裡執行 `bash scripts/setup_wsl.sh`）。

這個腳本會做四件事，全部裝在專案資料夾內：

1. 下載可攜式 ffmpeg 與 ffprobe 到 `bin/`
2. 用 `python3 -m venv` 建立 `.venv/`
3. 安裝 Python 套件（faster-whisper、CTranslate2、transformers、OpenCC 等）
4. 檢查 CUDA 是否可用

第一次安裝約需下載 1～2GB，視網路速度約 5～15 分鐘。

> 語音辨識與翻譯**模型不在安裝階段下載**，而是第一次使用時才抓，
> 所以你只會下載自己真正會用到的模型。

## 使用教學

雙擊 **`啟動字幕翻譯器.bat`**。

### 基本流程

1. **加入影片** — 按「加入影片…」可多選，或「加入整個資料夾…」批次匯入（會連子資料夾一起掃）
2. **選擇語言** — 「影片語言」留在「自動偵測」通常就夠；「翻譯成」選你要的目標語言
3. **選擇翻譯引擎** — 預設是本地開源模型，不用設定也不花錢（見下節）
4. **選擇輸出方式** — 預設只輸出 `.srt`
5. 按 **「開始處理」**

處理過程中，進度列會顯示目前階段與預估剩餘時間，執行紀錄會列出每個產出檔案。

### 字幕輸出方式

| 選項 | 產出 | 速度 | 適合 |
| --- | --- | --- | --- |
| 只輸出 `.srt` | `影片名.zh-TW.srt` | 最快 | 用播放器掛字幕、之後要修字幕 |
| 嵌入軟字幕 | `影片名.subbed.mp4` | 快（不重新編碼畫面）| 一個檔案搞定，字幕還能開關 |
| 燒錄進畫面 | `影片名.hardsub.mp4` | 慢（要重新編碼）| 手機、電視、社群平台 |

「字幕內容」可選只有譯文、只有原文，或雙語（譯文在上、原文在下）。

### 術語表

介面下方的「翻譯提示 / 術語表」可以寫任何給譯者的指示：

```
這是動畫，男主角叫「悠真」，女主角叫「紗織」。
「ギルド」統一譯成「公會」。
語氣輕鬆一點，不要用太正式的書面語。
```

對長影集特別有用，能讓整部片的譯名與語氣保持一致。

### 檔名重複的處理

批次匯入常會遇到 `第一季/01.mp4` 和 `第二季/01.mp4` 這種同名檔案：

- **輸出到影片原本的資料夾**（預設）：各自寫回自己的目錄，不會互相影響
- **輸出到同一個資料夾**：後面的會自動冠上來源資料夾名，存成 `第二季_01.zh-TW.srt`，
  不會蓋掉先處理好的那一份；執行紀錄也會寫明改成什麼名字

清單裡出現同名檔案時，會自動顯示上一層資料夾（`第一季\01.mp4`），才分得出誰是誰。

## 翻譯引擎怎麼選

| 引擎 | 費用 | 一小時影片 | 品質 |
| --- | --- | --- | --- |
| **本地開源模型**（預設）| 免費 | 約 1.5 小時 | 好，但日語慣用語會出錯 |
| **Google 免費翻譯** | 免費 | 約 6 分鐘 | 普通，且很常被限流 |
| **不翻譯** | — | — | 只產生原文字幕 |

本專案**不使用任何需要金鑰的雲端翻譯服務**，介面上也沒有填金鑰的地方。
本地模型是**整批送出並帶前文上下文**翻譯，所以人稱、語氣、專有名詞能前後一致，不是逐句機翻。

### 本地模型

模型由 CTranslate2 驅動，不需要額外安裝執行環境，存放於 `models/translate`。

| 模型 | 下載 | 速度 | 說明 |
| --- | --- | --- | --- |
| **Qwen3 4B** | 2.5GB | 11.7 秒/句 | 預設。8GB 顯卡剛好夠 |
| Qwen3 8B | 5.7GB | 16.3 秒/句 | 語氣略好但也會漏字，慢 40%，顯存吃到 6.1GB |
| NLLB-200 1.3B | 1.4GB | 0.02 秒/句 | 快上百倍，但一條字幕含兩句話時容易漏譯整句 |

**本地翻譯很慢，這是最大的取捨。** 一小時影片要跑 1.5 小時以上（還要加語音辨識時間）。
趕時間的話可以改用 NLLB（快上百倍，但長句會漏譯），或先只輸出原文字幕。

### 繁體中文處理

目標語言選「繁體中文」時：

1. 提示模型使用台灣用語
2. 譯文用 OpenCC（`s2twp`）轉台灣正體，連詞彙一起換（网络→網路、软件→軟體）
3. 再補一張對照表處理 OpenCC 不管的口語（早上好→早安）

像「質量」（物理學的 mass）、「數據」、「用戶」這類台灣也在用的詞不會被動到。

## 語音辨識怎麼選

預設 **large-v3-turbo**，日、中、韓、英實測皆正確。
偵測到 NVIDIA 顯示卡就用 GPU，否則自動退回 CPU。

**中文會自動輸出繁體。** Whisper 的中文輸出幾乎都是簡體（「欢迎收看今天的节目」），
所以辨識完會用 OpenCC 轉成台灣正體。目標語言選「簡體中文」時就不轉。

### 為什麼不用其他模型

- **Parakeet / Canary**（NVIDIA）：榜單上英文表現更好、速度極快，但**只支援歐洲語言**，日中韓都不支援。
- **kotoba-whisper / anime-whisper**：日語特化，日語標點確實較漂亮，但它們是**日語單語模型**。
  實測餵中文會輸出「人工知恵の発展」、餵韓文會輸出「この映像の9月 始まる」，完全是亂碼。
  只有整批都是純日文影片時才適合。

## 實測數據

測試環境：RTX 5060 8GB、WSL2 Ubuntu 24.04。

### 語音辨識：turbo vs large-v3

素材為日中韓英四語，語速加快 25%、混入背景雜訊（乾淨的語音兩者都接近滿分，分不出高下）。
以 CER（字元錯誤率）計分——中日韓沒有詞的空白分界，WER 不適用。

| | large-v3-turbo | large-v3 |
| --- | --- | --- |
| 日文 | 6.0% | 6.0% |
| 中文 | 6.9% | 5.2% |
| 韓文 | 4.5% | 4.5% |
| 英文 | 10.3% | 10.3% |
| **平均 CER** | **6.9%** | **6.5%** |
| **四段總辨識時間** | **6.0 秒** | **193.9 秒** |
| 模型載入 | 13 秒 | 300 秒以上 |

**結論：用 turbo。** 準確度只差 0.4 個百分點（而且只差在中文），速度差 33 倍。
跑過兩次確認不是首次編譯造成的假象。差距遠超官方宣稱的 5～8 倍，
推測是 CTranslate2 對 Blackwell 架構沒有 large-v3 的最佳化 kernel——
turbo 的 decoder 只有 4 層，large-v3 有 32 層，受影響小得多。

### 翻譯：Qwen3 4B vs 8B

10 句日文對白，含敬語、粗話、慣用語、專有名詞。

| | 4B | 8B |
| --- | --- | --- |
| 速度 | 11.7 秒/句 | 16.3 秒/句（慢 40%）|
| 漏譯 | 0/10 | 0/10 |
| 顯存 | 約 3GB | 約 6.1GB |

品質互有勝負，不是「8B 一定比較好」：

| 原文 | 4B | 8B |
| --- | --- | --- |
| 今日はいい天気ですね | 今天**天**氣真好呢 | 今天氣真好呢（漏字）|
| 来週の水曜日 | **下**週三 | 週三（漏掉「下」）|
| あいつ、また遅刻しやがった | 那個**人**又遲到了 | 那個**傢伙**又遲到了（語氣較準）|
| そんなこと言われても | 說這種話也太過分了（加譯）| 就算這樣說，我這邊也覺得困擾 |

**兩者共同的弱點是日語慣用語**：

- 「顔が広い」（人脈廣）→ 4B「他臉頰寬廣」、8B「他臉廣」
- 「乗り遅れる」（沒趕上車）→ 4B「坐過車了」、8B「搭錯電車」

這是這個量級的開源模型目前的限制。

## 專案架構

```
backend/            實際處理流程（跑在 WSL 裡）
  cli.py            主流程：讀取工作單、逐檔處理、以 JSON 逐行回報進度
  config.py         路徑、語言表、預設值
  transcribe.py     語音辨識（faster-whisper）與中文繁體化
  translate.py      翻譯引擎的選擇、Google 備援、台灣用語處理
  ct2_translate.py  本地開源模型（CTranslate2 跑 Qwen3 / NLLB）
  subtitles.py      SRT 排版、平衡折行、時間軸整理
  media.py          ffmpeg 封裝：探測、抽音軌、掛字幕、燒字幕
gui/app.pyw         Windows 圖形介面（tkinter，只用標準函式庫）
scripts/
  setup_wsl.sh      環境安裝
  run_backend.sh    設好 CUDA 函式庫路徑後執行後端
```

### 為什麼分成兩邊

圖形介面跑在 Windows（檔案選取方便、不需額外安裝），
運算跑在 WSL（CUDA、ffmpeg、Python 套件生態都比較順）。

兩邊用 **JSON Lines** 溝通：介面把設定從 stdin 餵給後端，
後端把進度一行一個 JSON 寫到 stdout。這樣不必額外架 server，
也讓後端能單獨用指令列測試：

```bash
echo '{"files":["/mnt/d/video.mp4"],"model":"deepdml/faster-whisper-large-v3-turbo-ct2",
"source_lang":"auto","target_lang":"繁體中文","engine":"local",
"local_model":"ctranslate2-4you/Qwen3-4B-ct2-AWQ","subtitle_mode":"srt","layout":"target"}' \
  | bash scripts/run_backend.sh
```

### 幾個實作上的細節

- **燒字幕的路徑跳脫**：ffmpeg `subtitles` 濾鏡對冒號、引號、逗號很敏感，
  跳脫規則又依版本而異。這裡不跳脫，而是把字幕複製到乾淨的暫存目錄、
  切換工作目錄後只用相對檔名，專案放在含空白或中文的路徑也不會出錯。
- **中文字型**：WSL 裡沒有中日韓字型，燒字幕會變豆腐。
  程式會從 `C:\Windows\Fonts` 複製微軟正黑體到 `bin/fonts`（該目錄已被 git 排除，字型有版權）。
- **模型輸出容錯**：語言模型不會每次都照格式輸出，有的回 `{"translations":[...]}`，
  有的直接回裸陣列。解析器把常見的幾種形狀都接住，否則模型明明翻對了卻被當成失敗。
- **不交出假的成功結果**：翻譯超過半數失敗時直接報錯，
  而不是默默交出一份其實全是原文的「譯文」。

## 常見問題

**第一次執行卡在「辨識中」很久？**
顯示卡的運算核心要先編譯並快取，這是一次性的。之後會快很多。

**翻譯失敗了，辨識結果會不會白跑？**
不會。翻譯一失敗會先把原文字幕存成 `檔名.語言.srt` 再回報錯誤，
修好問題後可以直接拿這份字幕用，不必重跑辨識。

**燒硬字幕很慢？**
內附的 ffmpeg 沒有包 NVENC，硬字幕是用 CPU 編碼。
只輸出 `.srt` 或用軟字幕就沒這個問題。

**沒有 NVIDIA 顯示卡可以用嗎？**
可以，會自動退回 CPU，但慢上數十倍。建議搭配較小的模型。

**環境壞掉了？**
按介面右下角「安裝 / 修復環境」，或重新執行 `bash scripts/setup_wsl.sh`。
